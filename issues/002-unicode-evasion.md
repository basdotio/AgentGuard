# 002 — 零宽字符/同形字绕过正则，无 Unicode 归一化

- **类别**：检测绕过
- **严重程度**：高（可绕过任意基于命令名的规则）
- **状态**：**已修复**（`internal/detect/logical.go` + 新规则 `OBF-005`）

## 问题描述

规则是对**原始字节**的字面量正则。命令名里插入一个零宽空格（U+200B）、或用
同形字（如西里尔字母 `с` 冒充拉丁 `c`）替换一个字符，规则里的 `curl` / `eval` /
`bash` 就匹配不到，而 shell/解释器在实际执行时可能仍然识别或被诱导识别。

扫描前**没有做 Unicode 归一化 / confusable 折叠**，所以视觉上一模一样的命令
在扫描器眼里是另一个字符串。

## 出处

- 对抗语料反向断言：[cmd/aguard/adversarial_test.go:239](../cmd/aguard/adversarial_test.go)
  （`knownGap: "rules are literal regexes over the raw bytes; no unicode normalization / confusable folding runs first"`）
- ROADMAP "Known limitations" 明确列出。

## 影响

与 [001](001-line-continuation-evasion.md) 同级：低成本、可主动利用。零宽字符尤其隐蔽，
人工 review 也难发现。

## 修复方向

1. **归一化预处理**：匹配前对文本做 NFKC 归一化 + 剥离零宽字符（U+200B/U+200C/U+200D/U+FEFF），
   并做一层 confusable → ASCII 折叠（可用 Unicode confusables 表或精简自建表）。
   同样只用于匹配，原文与行号不变。
2. **附带信号**：文本中**出现**零宽字符或跨脚本混排本身就值得作为一个新维度的
   OBF 类 finding（"命令名里藏了不可见字符"几乎不会是良性的），可与归一化一起落地。
3. 修复后翻转对抗语料反向断言。

- [001](001-line-continuation-evasion.md)、[007](007-regex-precision-awaiting-ast.md)

## 修复记录

与 [001](001-line-continuation-evasion.md) 共用同一个词法 pass（`logical.go`）：

- 剥离不可见码点：零宽空格/连接符、软连字符，以及 **"Trojan Source" 那一类双向控制符**
  （U+202A–202E、U+2066–2069）——它们让源码**显示**成一个样子、**词法**上是另一个样子，
  和同形字是同一类谎言。
- 同形字折叠为 ASCII：手写一张精简表（西里尔/希腊/少数单字母 lookalike），
  **不引入 `golang.org/x/text`**——两个依赖的体积是这个项目明确的卖点，而目标不是通用
  同形字检测，只是让把西里尔 U+0441 塞进 `curl`、U+0430 塞进 `eval`/`bash` 这类写法仍然命中。
- **附带收益已落地**：不可见字符由 `INJ-004` 报出（在**原文**上匹配，所以剥离不会把它自己静音），
  同形字伪装由 **`OBF-005`** 报出。用 005 而不是 004，因为 `OBF-004` 已被外传链的"中途编码"
  环节占用（见 `EXFIL-003`）——两条规则共用一个 ID 会在每份报告里塌成一行、在基线文件里塌成一条。

  合并后这条改成了**一条规则**而不是我原来那种"在归一化过程里计数"。这是更好的形状：
  "混排"直接编码进模式（要求同一 token 内同时有 ASCII 和西里尔/希腊字母），于是我花了三轮才
  测出来的三个精度区分**自动成立**——中文标点不是字母、整词外语没有相邻的 ASCII 字母、
  行尾 CR 与 BOM 都不是字母，一个都匹配不上。

### 精度是先测量、后落地的（issue 011 的教训）

第一版把排版标点和字母同形字放在同一张表里计数，拿本仓库自己的中文文档一扫：
**47 个 "homoglyph"、3 份文件、100/100 掉到 88/100、三条 medium**。`——` 和 `""` 是中文的
写法，不是攻击者藏命令的方式。一个会在自己项目 README 上报警的检测器，会被关掉。

三个区分修好了它，每个都有测试：

1. **排版标点只折叠、永不计数**（`punctFold`）。只有能改变 shell 解析的字符值得折叠
   （`ǀ`/`｜`→`|`、`∕`→`/`），而它们本身都不构成证据。
2. **整词外语不是伪装**。伪装的本质是**同一个 token 内混排**：把西里尔 U+0441 粘在拉丁 `url` 前面，
   因为它必须**看起来像**一个 ASCII 命令名。README.zh-CN.md 里有个俄语词
   俄语词 triazh（西里尔拼写），第一版报了三个同形字。修正后只有**作者原本就写下的** ASCII 字母才算混排证据——
   第二版还错过一次：折叠产生的字母互相把对方当作"ASCII 证据"，所以要排除**所有**折叠位置。
3. **行尾 CR 是换行的另一半**，不是隐藏字符。计数它会让每个 Windows 编写的文件按行数报警；
   文件开头的 BOM 同理（合法的编码标记）。行**中间**的 CR 仍然计数。

最终测量：良性中文文档 **100/100 零 finding**；三种绕过（西里尔、零宽、续行）**全部命中
EXEC-001**，其中两个额外报出 OBF-004。

对抗语料断言已翻转为 `wantCaught: []string{"EXEC-001", "OBF-004"}`。
