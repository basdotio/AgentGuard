## 判定口径

- **检测绕过**：攻击者读过本扫描器源码后可以主动利用的手法，多数已由对抗语料
  ([cmd/aguard/adversarial_test.go](../cmd/aguard/adversarial_test.go)) 用**反向断言**固化——
  修复后对应测试会失败，提醒同步更新断言与本目录状态。
- **覆盖缺口**：有内容没被读到。"部分缓解"指未读行为已通过 `COV-000` / `SUP-004`
  通报或部分拦截，但内容本身仍未被扫描。
- **能力边界（非缺陷，不单独立档）**：静态扫描无法证明恶意、无法观察运行时行为、
  无法还原强混淆载荷意图、不连接 MCP 端点、不检查依赖内部。这些是产品定位
  （见 README "Capability boundary"），修不掉，只能靠 LLM 裁判/运行时监控等新特性绕开。

## 状态取值（封闭集，只能用这六个）

| 状态 | 含义 |
|---|---|
| `已修复` | 修了，且有回归测试或反向断言钉住 |
| `部分修复` | 修了一部分，正文说清修了哪半、剩哪半 |
| `未修复` | 问题仍在。**"还没人决定要不要做"也归这一档** |
| `进行中` | 有人正在做 |
| `设计取舍` | 不是 bug，是权衡的结果，记录在案 |
| `不规划` | **已经决定不做**，正文必须写出否决理由和代价 |

**`未修复` 与 `不规划` 是最危险的一对** —— 此前它们以"未规划 / 不规划"的形式并存，一字之差
而含义相反：前者是"还没人定"，后者是"定了不做"。现在只保留 `不规划` 表示后者。

## 什么该进这里

一句话判据：**这条修完之后，这段文字还有没有价值？**

- **有 → 这里。** 否决记录、能力边界、结构性限制、失败尝试的量化代价。`011` 记的是一次失败
  修复的代价（100→69，15 条发现 8 条 high，已回退，回归测试锁死），`018`/`020` 是"实测否决，
  不要再论证" —— 工作项文档结构上装不下这类知识。
- **没有 → 不进。** 一条 `chmod` 的复现脚本，修完就是噪音；修法和验收写在修它的那次改动里。

**否决要留痕**：一件排过期的事被否决时，它**变成**一条 issue（带否决理由和代价）。
静默放弃会丢掉决策，下一个人会再论证一遍。

## 维护约定

- 修复一个问题：更新对应文件的"状态"和索引表，同时更新对抗语料中被反向断言的行。
- **这条约定只对"检测绕过"类有强制力，其余类别会漏。** 检测绕过类在
  `cmd/aguard/adversarial_test.go` 里有反向断言，修好时测试变红，**那是一个强制函数**；
  其他类别没有对应装置，所以只能靠人记得。后果已经发生过两次：`012` 的功能早已做完而状态
  停在"部分实现"并与 `020` 互相矛盾；`016` 最大的一次缓解改了 `008` 却漏了它自己。
  给其他类别造强制函数是一个设计任务，不是文档编辑，尚未排期。
- 新发现问题：按下一个编号建文件，格式对齐现有条目（问题描述 / 出处 / 影响 / 修复方向）。
- 本目录不追踪常规 feature（去 ROADMAP），只追踪缺陷、绕过、覆盖缺口与结构性限制。
