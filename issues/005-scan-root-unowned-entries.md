# 005 — `scan --root` 对无主顶层条目既不扫也不报

- **类别**：覆盖缺口
- **严重程度**：高（**唯一一个连覆盖备注都没有的缺口**）
- **状态**：**已修复**——松散的代码/文档文件已被读取；顶层目录不读是设计决定，不是缺口

## 问题描述

root 扫描只读**已知的子布局**（`skills/`、`settings.json`、`plugins/` 等）。
任何 collector 不认领的东西不会被读：

- `~/.claude` 顶层的散装脚本；
- `skills/` 下没有 `SKILL.md` 的目录。

这些内容既**不扫描**，也**不产生 `COV-000`**——与其他所有缺口不同，它在报告里
完全不留痕迹。"我没审到这个"和"这个没问题"在这里被混为一谈，而这正是本工具
存在的意义所在。

## 与 `check` 的区别（已修的那一半）

`check` 曾有同样的问题：一个没有 `SKILL.md` 的裸目录会落到 root collector，
后者找不到已知布局于是**什么都没读**，顶层的恶意 `install.sh` 得到 100/100 并
退出 0。`check` 已改为分层路由（单文件 → `SKILL.md` → plugin manifest → root →
整树读取），不再走进这个坑。**`scan --root` 仍然有这个缺口。**

## 出处

- ROADMAP "Known limitations" 最后一条明确记录（"and (unlike every other gap) not noted either"）
- 路由实现：[internal/collect/collect.go:50](../internal/collect/collect.go) 起
  （`CollectAll` 与路由标记）

## 修复方向

两条路，可组合：

1. **补通报（低成本、先行）**：遍历 root 顶层条目，凡不属于任何 collector 认领范围的，
   每个发一条 `COV-000`。至少让缺口可见——这符合项目"跳过必须发声"的铁律。
2. **补扫描（彻底）**：扩展 collector，把无主的顶层文件与 `skills/` 下无
   `SKILL.md` 的目录也收集为产物（可复用 `check` 的整树读取路径）。
   需要考虑归因：这些内容挂在哪个产物名下、如何打分。

建议先做 1（一次提交即可闭合"静默"这一最严重的性质），再评估 2。

## 关联

- 已修的对照实现：`check` 的分层路由（ROADMAP "check is a gate" 一节）

## 修复记录（第 1 步：让缺口发声）

`internal/collect/unowned.go`：`CollectAll` 最后一步遍历 root 顶层，凡不属于任何 collector
认领范围的条目，聚合成**一条** `COV-000`（medium，维度 0，不计分）并**点名**列出。
"3 个条目未读"促成不了任何动作，"install.sh, tools 未读"会。

它**不读任何文件**——只 stat 顶层。整件事的意义就是说清楚什么没被读，而一个为了描述
"没打开"而去打开文件的函数是错的形状，也会成为敌意目录树诱使本工具读东西的一条新路径。

**运行时状态按名字排除**（caches、transcripts、`history.jsonl`、`sessions`、`plans` 等）：
它们不是人写的内容，Claude Code 自己会按龄清理，而**一条在每个环境都会触发的披露就是墙纸**。

`ownedNames` 手工维护在 unowned.go 里，并有 `TestOwnedNames_MatchesWhatCollectorsRead`
断言它与 `CollectAll` 实际读的布局一致。之所以不从 collector 自动派生：那需要把注册调用
穿过十一个 collector，而清单过期的后果（把已读的目录报成未读）是操作者可以忽略的一条备注，
漏掉一个 collector 的后果恰恰是这个文件要消灭的那种静默。

## 仍然缺的（第 2 步：真正扫描）

无主条目要被扫描，需要**产物身份**（挂在什么名字下）、**归因**（finding 报给谁）和
**计分位置**。这比"让缺口可见"大得多，所以刻意分开：一条操作者今天就能据以行动的披露，
胜过一个吵一周的计分模型。


## 补充（合并 `feat/escalation-plan` 之后）

第 2 步也做了，而且做法比本文当初设想的更好——**判据不是名字、也不是文件形状，而是"agent 有没有
加载路径进去"**：

- 顶层的**松散文件**小、有界、像人写的 → 看起来像解释器会跑的东西（按扩展名或 shebang）或者
  像指令（`.md`）就**读**。Claude Code 自己的顶层条目是 `.json`/`.jsonl` 状态，正好在线的另一边。
- `skills/`、`agents/`、`commands/` 是**加载命名空间**，缺 manifest 的内容仍然在 agent 会看的地方,
  所以照读。
- 顶层**目录**一律不读。体积和用户数据都在那儿（`sessions/`、`projects/`、`file-history/`、
  `shell-snapshots/`——都是用户自己的 transcript 和 shell 快照），把它们读进报告（或者带 `--llm`
  送去端点）等于**拿一个盲区换一个更糟的泄露**。按名字披露，让这个决定可见。

那一侧还记录了两个失败的早期版本，值得留着：手写"运行时状态名单"会漏（等于承诺永远追踪别人的
目录布局）；"含可执行文件的目录就读"也错，因为 `shell-snapshots/` 里**全是** shell 脚本——它们
就是用户代码的快照。**形状分不开"人写的内容"和"机器生成的状态"，当状态本身就是由内容构成时。**

以及一个我们没想到的反常效应：每个无主条目变成一个 100 分的产物，而环境分是**平均值**，
所以更彻底的扫描反而让分数**上升**（86→97→93），纯靠稀释已有的 finding。**note 不是产物，
所以披露不花钱。**

因此本条关闭：顶层目录不读**是设计决定而不是缺口**，且已在报告里点名。
