# 004 — 未知扩展名文件只通报不扫描

- **类别**：覆盖缺口
- **严重程度**：中（内容未读，但已被点名披露）
- **状态**：**已修复**

## 问题描述

静态引擎按**扩展名允许列表**决定读什么。无扩展名的文件（如 `bootstrap`）和
点文件（如 `.bashrc`）不匹配列表里任何一项，因此**不被扫描**。

这两类恰好是 shell 脚本最自然的存在形式，攻击者不需要任何技巧，只要不给文件加
`.sh` 后缀。

## 已有缓解

内容嗅探（content sniff）会区分可读文本与二进制，文本类的未扫描文件会按产物
聚合成一条 `COV-000` 备注并**点名列出**——"没读"不会伪装成"没问题"。但它只是
披露，不参与打分，也不会让门禁失败。

## 出处

- 允许列表：[internal/detect/detect.go:25](../internal/detect/detect.go)（`textExts`），
  使用点：[internal/detect/detect.go:339](../internal/detect/detect.go)
- 对抗语料反向断言：[cmd/aguard/adversarial_test.go:206](../cmd/aguard/adversarial_test.go)
- README "Coverage caveats" + ROADMAP "Known limitations"

## 修复方向

1. **改为按嗅探扫描，而非按扩展名扫描**：既然已经有 content sniff 能判断"是文本"，
   就让判定为文本的文件直接进入规则引擎，扩展名只作为快速路径。这是最彻底的修法，
   也顺手关掉整类绕过。
2. 或**扩展 `textExts`** 并把"无扩展名 + shebang 开头"识别为脚本。成本更低，
   但仍是黑名单式思路，下一个变体又会漏。
3. 二进制文件保持不读（当前行为正确），继续走 `COV-000`。
4. 修复后翻转对抗语料反向断言。

## 修复记录

采用了"修复方向 1"（最彻底的那条），而且**成本远低于当初的估计**：`looksTextual()` 早就存在，
只是接在了**通报**上（"这个 skip 值不值得发一条 COV-000"）。那和"要不要读"是同一个问题，
所以现在由它决定**读**。扩展名允许列表退化为快速路径。

这是整份对抗语料里最便宜的绕过：**不需要任何技巧，只要不加后缀**。

二进制仍然不读、仍然不通报——PNG 不是指令，为每张图片发一条备注会淹没真正有意义的备注。

同时删掉了"按扩展名跳过"的那条备注（`unscannedExtNote`）：它现在永远不会触发，而**一条
永不触发的备注比没有备注更糟**——它看起来像一层保护，其实那层保护并不存在。源码里留了
一段说明它为什么消失，避免有人再加回来。

精度的另一半同样有断言：`LICENSE`、`Makefile`、`NOTICE`、`.editorconfig` 现在也会被读，
而**读它们不得凭空产生 finding**。多打开文件只有在报告对无聊内容保持安静时才算改进。

对抗语料断言已翻转为 `wantCaught: []string{"EXEC-001"}`。
